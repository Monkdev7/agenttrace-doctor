Selection transitions (no stale selections)

  • Click finding → set finding, clear event, highlight its eventIndices.
  • Click event → set event, clear finding; details show the event + all findings citing its index.
  • Failed upload → preserve current trace + findings; show error only.
  • Switch sample / valid upload → recompute findings, clear selections + expanded + error.
  • Highlight always visually distinct from execution status.

Detector Algorithms

D1 — Repeated tool calls (mandatory) 
calls = tool_call events, in order
 (tool_result ignored for sequencing)
walk calls, tracking a run:
  same tool_name AND same argsKey
     → extend run
  else
     → if run ≥ 3: emit
       start new run
end → if run ≥ 3: emit
  • Run of 2 → nothing.
  • Cite every call in the run.
  • Two runs split by another call → two findings.
  • Labeled possible loop, never confirmed.
D2 — Explicit tool errors (mandatory) 
for each tool_result
    with status == "error":
  indices = [result.index]
  if call_id resolves:
     indices += [call.index]
  emit finding(indices, error)
  • Unmatched call_id → still emit, cite result only (no crash).
  • Show the real error message; no invented root cause.
  • Repeated-failure aggregation = stretch D3, must not delay D1/D2.

Stable normalization: recursively sort object keys, preserve array order, strip nothing (timestamps/nonces kept). Equal stableStringify output ⇒ identical args.

Stack & Run

  • React 18 + Vite 5 + TypeScript · Zod · Vitest · pnpm. No runtime services, keys, or cost.
  • pnpm install → pnpm dev (open the local URL) → record the demo. pnpm build / pnpm test.
  • Submission: demo video and public GitHub repo. Static deploy optional, only after mandatory tests pass.

Tests & Failure Modes

Vitest (pure functions)
  • normalize: key-order independent, array-order kept, nothing stripped
  • D1: ≥3 fires, 2 doesn't, resets, results-skipped, two runs → two
  • D2: error → finding, call_id links, unmatched doesn't crash
  • validate: malformed JSON, missing status, wrong type, valid passes
  • report: cited-only, safe escaping, filename
Failure modes → fallback
  • Bad JSON → inline parse error; trace kept
  • Schema error → specific per-event message; trace kept
  • Unmatched call_id → finding on result only
  • Missing optional fields → rendered gracefully
  • All-clean trace → EmptyFindings (not an error)
