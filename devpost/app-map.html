What it is

A browser-only React + TypeScript tool that loads an AI agent's execution trace, runs two deterministic detectors over it, and explains each finding with a link to the exact events that triggered it. No backend, no API key, no network. The main pieces:
  • Pipeline (src/lib/) — pure functions: validate → normalize → detect → report.
  • Detectors (src/lib/detectors/) — repeated calls (possible loop) and explicit errors (confirmed).
  • Workspace (src/App.tsx + src/components/) — the two-panel timeline + findings UI.
  • Samples (src/samples/) — three bundled traces; Repeated Tool Calls loads by default.

One real action, end to end

You open the app and the "possible loop" finding appears. Here is the path that produces it:
sample JSON
src/samples/*.json → validate
lib/validate.ts → normalize
lib/normalize.ts → detect
detectors/index.ts → render
App.tsx → FindingsPanel

Clicking the finding sets a selection in App.tsx; the highlighted event set is derived from it (lib/selection.ts → highlightedIndices) and the timeline rows light up — highlight (cyan) stays distinct from status (green/amber).

A 3-stop code route

  1. The rule — src/lib/detectors/repeatedCalls.ts, function detectRepeatedCalls and the MIN_RUN = 3 constant. This is where "3+ identical consecutive calls = possible loop" is implemented; it reuses the argsKey computed during normalization, so it never re-stringifies.
  2. The proof — tests/repeatedCalls.test.ts. Nine cases pin the rule, including "two identical calls produce no finding" (the 3-vs-2 boundary) and "two qualifying runs → two findings".
  3. The screen — src/components/FindingCard.tsx. The four labeled parts (fact · evidence · explanation · fix) and the certainty badge; evidence event IDs are buttons that call onGoToEvent to jump to the timeline.
(Reference route — read it in your editor; it was not a live guided walk.)

To change this, start here

  • Change the loop threshold → MIN_RUN in src/lib/detectors/repeatedCalls.ts (then update tests/repeatedCalls.test.ts).
  • Edit a sample's story → src/samples/*.json (the Repeated Tool Calls sample now tells a coherent Paris-weather loop story).
  • Retune the look → CSS variables in src/styles/theme.css (palette/fonts live in one :root block).
  • Change the report → src/lib/report.ts (generateReport, reportFilename); escaping is in escapeMd.
  • Add a third detector → write src/lib/detectors/<name>.ts and add one line to src/lib/detectors/index.ts.

A practice to reuse

Pin a rule to a checkable test before implementing it. In this build the repeated-call rule was decided precisely in planning (prd.md > Resolved Decisions), then locked by tests in tests/repeatedCalls.test.ts before the UI depended on it. The payoff showed up concretely: when the Repeated Tool Calls sample was rewritten for narrative, a hardcoded assertion in tests/workspace.test.ts failed until it was corrected — the test caught the change instead of it slipping through silently. Next project: write the acceptance check first, and the agent is held to your intent rather than drifting from it.
