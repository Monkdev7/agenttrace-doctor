AgentTrace Doctor — PRD

Product Requirements · status: draft · Markdown (prd.md) is canonical
A local, evidence-first debugging tool: load an agent's execution trace, detect suspicious patterns with deterministic rules, and explain each finding with a link to the exact events that triggered it. No LLM · no API key · no backend.

The Core Journey

Open Loads straight into the Repeated Tool Calls sample — timeline + findings already populated.
Orient Header: sample selector (3 samples) · Upload JSON · Export report.
Read Two panels — timeline left, findings right.
Connect Click a finding → events highlight. Click an event → see detail + which finding cites it.
Bring your own Upload JSON; invalid files show an inline error and keep the current trace.
Export Download a Markdown report (copy as backup). Fully local.

Behaviors & States

Finding cards — fact vs. inference▾
  • Explicit errors → labeled confirmed errors reported by the trace; show the real message + event IDs; no invented root cause.
  • Repeated calls → state the fact; label interpretation "Possible loop / Worth investigating."
  • Four parts always visually separated: fact · evidence · explanation · fix — via layout & labels, not color alone.
  • Inline evidence preview (tool + args / error), truncated with expand; event refs jump to the timeline.
Timeline event detail▾
  • Each row: event ID · type · tool name · status indicator.
  • Tool calls → concise arg summary, expand for full JSON. Results → OK (summary only if present in input). Errors → short message preview, expand for full.
  • Missing/empty fields handled gracefully. Select reveals detail in place — no scroll loss.
  • Status colors: ok=green · error=amber · repeated=primary "Watch" (never error-colored).
Upload & validation (non-destructive)▾
  • Invalid upload never wipes the current trace or blocks the workspace.
  • Inline, dismissable error names the event ID/index, the bad field, the expected format, and how to fix — e.g. "Event #4 is a tool_result but has no status field."
  • Malformed JSON → parse error with line/column when available. Workspace replaced only after a valid parse.
Clean Run — empty findings▾
  • "No issues detected by the current detectors," with events-analyzed and distinct-tool counts where computable.
  • Explicitly notes: no issues by the implemented rules — not a proof of correctness. This is the kernel defending itself.
Markdown report▾
  • Title + timestamp · source/counts · detector summary · one section per finding (fact, cited IDs, preview, explanation, rule, fix) · no-findings statement · limitations note.
  • Only cited events included, safely escaped. Full raw trace excluded.
  • Download .md primary; Copy secondary; identical content; fully local.

Look & Feel

Primary — cyan (selection, "watch")
Success — muted green (ok)
Error — muted amber (real failures only)
Surface — deep navy / charcoal

System sans for UI, system monospace for IDs/JSON/errors. No external fonts. No decorative red. Status legible without color.

Boundary — building vs. deferred

Building (MVP)

  • Dark two-panel workspace + header
  • 3 samples (Repeated · Failure · Clean)
  • Owned JSON schema + validation + stable arg normalization
  • Detector 1 & Detector 2 (mandatory)
  • Timeline, finding cards, bi-directional highlight
  • Markdown report (cited events only)
  • Responsive layout

Deferred / Non-goals

  • Detector 3 (same tool fails N+×) — stretch, additive only
  • PDF / other exports
  • Format adapters (LangSmith, OTel, OpenAI)
  • Persistence / saved reports
  • LLM diagnosis · general cycle detection
  • Accounts · API keys · backend

Open Questions

  • Report filename convention — minor; settle in 4-spec or build. Does not block approval.
  • Detector 1 threshold/window (2+ identical calls; consecutive vs. anywhere) — a detection detail for 4-spec, before the detector is built. Does not block product approval.
